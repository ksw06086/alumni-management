# 테스트 시작 순서

## 먼저 확인할 로컬 자동 테스트

저장소 루트에서 실행합니다.

```powershell
npm test
npm run build
```

Apps Script 테스트는 Google 서비스를 모의한 단위 테스트이며 실제 스프레드시트에는 접근하지 않습니다. Worker 테스트도 프록시 응답을 모의합니다. 따라서 Google OAuth와 실제 Apps Script·Cloudflare 배포 연결은 수동으로 확인해야 합니다.

## 수동 통합 테스트 준비

1. 운영 스프레드시트를 복사해 테스트용 스프레드시트를 만듭니다. 이후 등록·수정·삭제 테스트는 복사본에서만 수행합니다.
2. 테스트용 Apps Script 프로젝트의 스크립트 속성 `SPREADSHEET_ID`를 복사본 ID로 설정하고 `GOOGLE_CLIENT_ID`가 프런트엔드 OAuth Client ID와 같은지 확인합니다.
3. 복사한 스프레드시트에 연결된 테스트용 Apps Script 프로젝트에서 최신 `apps-script/Code.gs`를 반영해 웹 앱 새 버전을 배포합니다.
4. 테스트용 Worker 서비스를 별도로 만들고 `APPS_SCRIPT_URL`을 테스트 Apps Script의 `/exec` URL로, `ALLOWED_ORIGINS`를 `http://localhost:5173`로 설정합니다. 운영 Worker 설정을 테스트용 주소로 바꾸지 마세요.
5. 프로젝트 루트의 `.env.local`에 `VITE_API_BASE_URL`을 테스트 Worker URL로 설정하고 `VITE_GOOGLE_CLIENT_ID`도 지정합니다. 저장소 루트에서 `npm run dev`를 실행해 `http://localhost:5173`을 엽니다.

## 권장 확인 순서

1. 관리자 Google 로그인 후 테스트 연도 시트가 열리고 학생 수와 상태별 숫자가 표시되는지 확인합니다.
2. 검색과 상태 필터를 각각 적용하고 결과 행과 총인원이 맞는지 확인합니다.
3. 테스트용 학번으로 학생 한 명을 등록합니다. 같은 학번을 다시 등록하면 중복 오류가 나야 합니다.
4. 방금 등록한 학생 정보를 수정하고 새로고침해 수정 내용이 남는지 확인합니다.
5. CSV를 내려받아 한글이 깨지지 않는지 확인합니다. Excel에서 수식처럼 보이는 입력값은 텍스트로 처리되는지도 확인합니다.
6. 통계 화면에서 해당 연도와 상태별 합계가 시트 데이터와 일치하는지 확인합니다.
7. 작업 기록 화면에서 등록·수정 작업을 확인합니다. 일반 사용자 계정으로 로그·사용자 관리 접근이 거부되는지도 확인합니다.
8. 관리자 화면에서 테스트 계정을 추가하고, 비활성화한 다음 해당 계정의 요청이 차단되는지 확인합니다.
9. 마지막에 테스트 학생을 삭제하고 시트에서 사라졌는지와 삭제 로그가 남았는지 확인합니다.
10. 로그인 상태에서 같은 탭을 새로고침해 세션이 복원되는지 확인합니다. 그런 다음 로그아웃하고 새로고침해 로그인 화면이 그대로 나오는지 확인합니다.

실제 서비스 전환 전에는 테스트용 Apps Script가 운영 스프레드시트 ID를 가리키지 않는지 다시 확인합니다.
